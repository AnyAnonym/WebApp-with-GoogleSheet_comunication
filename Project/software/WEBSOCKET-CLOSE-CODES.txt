================================================================================
WebSocket-Close-Codes - Bedeutung und Bewertung
================================================================================
Stand: v4.1.0, 2026-07-30

Dieses Dokument beschreibt die WebSocket-Schliesscodes des ePiber-Backends und
des Browserclients. Eine typische Backendmeldung lautet:

  dataProvider: Client <Verbindungs-UUID> getrennt (<Code> <Grund>)

Die UUID bezeichnet eine einzelne WebSocket-Verbindung. Ein Browser mit mehreren
Tabs oder ein Monitor nach mehreren Verbindungsversuchen kann daher mehrere UUIDs
erzeugen. Der Close-Code ist kein HTTP-Status und kein fachlicher API-Fehler,
sondern beschreibt das Ende einer WebSocket-Verbindung.


================================================================================
1. IM PROJEKT VERWENDETE CODES
================================================================================

Code | Bedeutung                    | Ausloeser / Erklaerung
-----|------------------------------|---------------------------------------------
1000 | Normale Trennung             | Der Browser ersetzt die Verbindung nach
     |                              | einer Sessionaenderung (`Session changed`),
     |                              | beendet den Client kontrolliert (`Client
     |                              | stopped`) oder schliesst regulaer.
     |                              | Kein Fehler.
-----|------------------------------|---------------------------------------------
1002 | Protokollfehler               | Der Browserclient hat vom Server ungueltiges
     |                              | JSON erhalten und beendet die Verbindung.
     |                              | Wiederholtes Auftreten muss untersucht
     |                              | werden.
-----|------------------------------|---------------------------------------------
1006 | Abnormale Trennung            | Es wurde kein regulaerer Close-Frame
     |                              | empfangen. Moegliche Ursachen sind
     |                              | Netzwerkabbruch, Prozessabbruch, ein toter
     |                              | Client ohne Pong, ein Sendefehler oder
     |                              | serverseitiges `terminate()`. Dieser Code
     |                              | darf nicht aktiv gesendet werden und wird
     |                              | lokal als Ergebnis der Trennung gemeldet.
-----|------------------------------|---------------------------------------------
1008 | Richtlinienverstoss           | Der Client hat das serverseitige
     |                              | Nachrichtenlimit ueberschritten
     |                              | (`Nachrichtenrate ueberschritten`). Das ist
     |                              | Last- und Missbrauchsschutz. Der aktuelle
     |                              | Browserclient behandelt den Code als
     |                              | dauerhaft und verbindet nicht automatisch
     |                              | neu.
-----|------------------------------|---------------------------------------------
1009 | Nachricht zu gross            | Eine WebSocket-Nachricht ueberschreitet
     |                              | `WS_MAX_PAYLOAD_BYTES`. Die `ws`-Bibliothek
     |                              | sendet dem Client 1009. Auf Serverseite kann
     |                              | derselbe Vorgang wegen des anschliessenden
     |                              | Abbruchs als 1006 erscheinen.
-----|------------------------------|---------------------------------------------
1011 | Interner Transportfehler      | Ein Monitorbefehl konnte nicht uebertragen
     |                              | werden (`Monitortransport fehlgeschlagen`).
     |                              | Monitor- und Netzwerkverbindung pruefen.
-----|------------------------------|---------------------------------------------
1012 | Dienstneustart                | Das Backend wird kontrolliert beendet oder
     |                              | neu gestartet (`Service restart`). Alle
     |                              | verbundenen Browser und Monitore werden vor
     |                              | dem Shutdown geschlossen. Normal bei
     |                              | `systemctl restart` und Deployments.
-----|------------------------------|---------------------------------------------
1013 | Voruebergehend nicht          | Der Client kann voruebergehend nicht bedient
     | verfuegbar                    | werden. ePiber verwendet den Code, wenn der
     |                              | Sendepuffer zu gross wird (`Client zu
     |                              | langsam`) oder ein Handshake wegen eines
     |                              | serverseitigen 503-Zustands fehlschlaegt.
     |                              | Direkt nach einem Backendstart kann dies
     |                              | auftreten, solange Tabellen initial geladen
     |                              | werden. Automatische Wiederverbindung ist
     |                              | vorgesehen.
-----|------------------------------|---------------------------------------------
4000 | Connect-Timeout               | Der Browser hat innerhalb von zehn Sekunden
     |                              | kein gueltiges `welcome` erhalten. Der Code
     |                              | wird clientseitig gesendet und fuehrt zu
     |                              | einem neuen Verbindungsversuch.
-----|------------------------------|---------------------------------------------
4001 | Veraltete Verbindung          | Der Browser hat laenger als die ausgehandelte
     |                              | Stale-Frist keine Servernachricht erhalten
     |                              | (`Stale connection`). Automatische
     |                              | Wiederverbindung ist vorgesehen.
-----|------------------------------|---------------------------------------------
4002 | Browser offline               | Der Browser hat ein Offline-Ereignis erkannt
     |                              | (`Browser offline`). Nach dem Online-Ereignis
     |                              | wird neu verbunden.
-----|------------------------------|---------------------------------------------
4003 | Monitorberechtigung ungueltig | Ein Monitortoken wurde rotiert oder
     |                              | widerrufen. Gruende sind unter anderem
     |                              | `Geraetetoken rotiert`, `Geraet widerrufen`
     |                              | und `Geraetetoken widerrufen`. Der Code ist
     |                              | terminal; die Monitorsitzung muss geprueft
     |                              | oder neu provisioniert werden.
-----|------------------------------|---------------------------------------------
4009 | Monitor doppelt verbunden    | Eine neue Verbindung desselben Monitors
     |                              | ersetzt die alte (`Neue Monitorverbindung`).
     |                              | Die alte Monitorseite zeigt an, dass der
     |                              | Monitor bereits in einem anderen Fenster
     |                              | verbunden ist. Der Code ist terminal.
-----|------------------------------|---------------------------------------------
4406 | ePiber-Protokoll inkompatibel | Das `hello`, die Protokollversion oder eine
     |                              | korrelierte Serverantwort ist ungueltig.
     |                              | Gruende sind `Protokollversion inkompatibel`,
     |                              | `Handshake fehlgeschlagen`, `Protocol
     |                              | mismatch` oder `Response endpoint mismatch`.
     |                              | Hauefige Ursache ist ein alter Browser-Tab
     |                              | mit veraltetem JavaScript. Der Code ist
     |                              | terminal und stoppt automatische Reconnects.
-----|------------------------------|---------------------------------------------
4408 | ePiber-Handshake-Timeout      | Die WebSocket-Verbindung wurde angenommen,
     |                              | aber innerhalb von `WS_HANDSHAKE_TIMEOUT_MS`
     |                              | kam kein vollstaendiges gueltiges `hello`.
     |                              | Ursachen koennen alte oder schlafende Tabs,
     |                              | Legacy-Clients, unterbrochene Ausfuehrung
     |                              | oder Netzwerkprobleme sein. Der Client darf
     |                              | mit Backoff erneut verbinden.


================================================================================
2. WEITERE STANDARD-CODES
================================================================================

Diese RFC-/WebSocket-Standardcodes werden von ePiber derzeit nicht gezielt als
fachliche Close-Gruende gesetzt. Browser, Proxy, Netzwerk oder WebSocket-Bibliothek
koennen sie dennoch melden.

Code | Bedeutung                    | Hinweis
-----|------------------------------|---------------------------------------------
1001 | Endpunkt verlaesst Verbindung| Typisch beim Schliessen oder Navigieren einer
     |                              | Browserseite. Je nach Browser kann stattdessen
     |                              | 1000 oder 1006 erscheinen.
-----|------------------------------|---------------------------------------------
1003 | Datentyp nicht unterstuetzt   | Der Endpunkt kann den empfangenen
     |                              | Nachrichtentyp nicht verarbeiten.
-----|------------------------------|---------------------------------------------
1004 | Reserviert                    | Darf nicht verwendet werden.
-----|------------------------------|---------------------------------------------
1005 | Kein Statuscode empfangen     | Darf nicht aktiv gesendet werden. Lokale
     |                              | Darstellung eines Close-Frames ohne Code.
-----|------------------------------|---------------------------------------------
1007 | Ungueltige Nachrichtendaten   | Nachricht entspricht nicht dem erwarteten
     |                              | Datentyp beziehungsweise Encoding.
-----|------------------------------|---------------------------------------------
1010 | Erweiterung erforderlich      | Ein Client verlangt eine nicht ausgehandelte
     |                              | WebSocket-Erweiterung.
-----|------------------------------|---------------------------------------------
1014 | Bad Gateway                   | Proxy oder Upstream war nicht erreichbar.
-----|------------------------------|---------------------------------------------
1015 | TLS-Fehler                    | Darf nicht aktiv gesendet werden. Lokale
     |                              | Darstellung eines TLS-/Zertifikatsfehlers.

Die Bereiche 3000 bis 3999 sind fuer registrierte Bibliotheks-/Frameworkcodes
vorgesehen. Die Bereiche 4000 bis 4999 sind private Anwendungscodes. ePiber nutzt
daraus 4000, 4001, 4002, 4003, 4009, 4406 und 4408.


================================================================================
3. RECONNECT-VERHALTEN DES BROWSERCLIENTS
================================================================================

Der Browserclient behandelt folgende Codes als terminal:

  1008  Nachrichtenlimit beziehungsweise Richtlinienverstoss
  4003  Monitor-Token rotiert oder widerrufen
  4009  Monitor bereits in einem anderen Fenster verbunden
  4406  Protokollversion beziehungsweise Nachrichtenkorrelation inkompatibel

Bei diesen Codes stoppt `Frontend/JS/dataClient.js` die automatische
Wiederverbindung. Ein ausdruecklicher, fachlich erlaubter Neustart der Verbindung
ist weiterhin moeglich.

Bei temporaeren Gruenden wie 1012, 1013, 4000, 4001 und 4408 wird grundsaetzlich
mit ansteigender Wartezeit bis maximal 30 Sekunden neu verbunden. Beim Wechsel
von offline zu online wird die Verbindung ebenfalls neu aufgebaut.

Bei 1000 `Session changed` erzeugt der Auth-Client unmittelbar eine neue
Verbindung mit dem aktuellen Sessioncookie. Bei 1000 `Client stopped` ist keine
Wiederverbindung beabsichtigt, weil die Seite oder der Client bewusst beendet
wurde.


================================================================================
4. BEWERTUNG TYPISCHER LOGFOLGEN
================================================================================

`1012 Service restart`
  Normal bei einem kontrollierten Backendneustart. Mehrere Meldungen bedeuten,
  dass mehrere Tabs, Browser oder Monitore verbunden waren. Jeder Client besitzt
  eine eigene Verbindungs-UUID.

`1013 Handshake fehlgeschlagen` direkt nach dem Backendstart
  Normaler temporaerer Zustand, wenn ein Client schneller reconnectet als der
  initiale Tabellenimport abgeschlossen ist. Bleibt 1013 nach erfolgreichem
  Initialload bestehen, muessen Backend-Readiness und Sendepuffer geprueft werden.

`1000 Session changed`
  Normal. Der Browser ersetzt eine anonyme oder alte Verbindung, nachdem der
  aktuelle Sessionzustand geladen oder geaendert wurde.

`4406 Protokollversion inkompatibel`
  Ein Client verwendet eine alte oder ungueltige Protokollversion. Alten Tab
  schliessen beziehungsweise Seite ohne Cache neu laden. Wiederholtes Auftreten
  nach Aktualisierung deutet auf einen Legacy-Client oder eine fehlerhafte
  Clientimplementierung hin.

`4408 Handshake Timeout`
  Einzelne Meldungen sind meist harmlos. Viele Meldungen direkt nach einem
  Neustart sprechen fuer alte, schlafende oder gleichzeitig reconnectende Tabs.
  Laeuft die Serie dauerhaft weiter, muessen offene Browser-/Monitorseiten,
  Browsercache, Proxyverbindung und die vom Client gesendete `hello`-Nachricht
  untersucht werden.

`1006` in Kombination mit `Max payload size exceeded`
  Der Client erhaelt in diesem Fall normalerweise 1009. Der Server kann wegen des
  anschliessenden harten Abbruchs lokal 1006 protokollieren. Beide Meldungen
  beschreiben dann denselben Vorgang.


================================================================================
5. HTTP-ABLEHNUNGEN VOR DEM WEBSOCKET-UPGRADE
================================================================================

Ein Fehler vor dem erfolgreichen WebSocket-Upgrade ist kein Close-Code. Der
Server lehnt den HTTP-Upgrade-Request stattdessen mit einem HTTP-Status ab:

  403  Origin nicht erlaubt
  404  Pfad ist nicht `/ws`
  429  Zu viele Verbindungsversuche oder Verbindungen derselben IP-Adresse
  503  Server wird beendet oder globale Verbindungskapazitaet ist erreicht

Da in diesen Faellen noch keine WebSocket-Verbindung und keine Client-UUID im
`clients`-Verzeichnis existiert, erscheint normalerweise keine Meldung
`dataProvider: Client ... getrennt`.
