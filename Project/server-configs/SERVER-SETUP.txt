3. PORT-ZUORDNUNG
================================================================================

System   | Caddy (extern)  | Backend (intern) | WebSocket-URL
---------|-----------------|------------------|---------------------------
piber    | 443 (HTTPS)     | 8080             | wss://epiber.at/ws
paj      | 8081 (HTTP)     | 8083             | ws://epiber.at:8081/ws
pk       | 8082 (HTTP)     | 8084             | ws://epiber.at:8082/ws

Hinweis: Nur das Live-System (piber) laeuft ueber HTTPS mit automatischem
Let's Encrypt Zertifikat. Die Testsysteme PAJ und PK laufen ueber HTTP.


================================================================================
4. ERSTEINRICHTUNG AUF DEM SERVER
================================================================================

4.1 Pakete installieren
-----------------------

  pacman -S nodejs npm caddy git


4.2 Benutzer anlegen
--------------------

  useradd -r -U -s /bin/nologin piber
  useradd -r -U -s /bin/nologin paj
  useradd -r -U -s /bin/nologin pk


4.3 Verzeichnisse anlegen
--------------------------

  mkdir -p /srv/http/ePiber/{piber,paj,pk}
  chown piber:piber /srv/http/ePiber/piber
  chown paj:paj     /srv/http/ePiber/paj
  chown pk:pk       /srv/http/ePiber/pk


4.4 Git-Repository klonen (3x)
-------------------------------

  cd /srv/http/ePiber/piber
  git clone <REPO_URL> .

  cd /srv/http/ePiber/paj
  git clone <REPO_URL> .

  cd /srv/http/ePiber/pk
  git clone <REPO_URL> .

  # Durch den Clone als root erzeugte Dateien den Service-Benutzern zuweisen:
  chown -R piber:piber /srv/http/ePiber/piber
  chown -R paj:paj     /srv/http/ePiber/paj
  chown -R pk:pk       /srv/http/ePiber/pk


4.5 Backend Dependencies installieren (3x)
-------------------------------------------

  cd /srv/http/ePiber/piber/Backend && npm install --production
  cd /srv/http/ePiber/paj/Backend   && npm install --production
  cd /srv/http/ePiber/pk/Backend    && npm install --production


4.6 Konfigurationsdateien erstellen (pro System!)
--------------------------------------------------

Jedes System benoetigt eine eigene .env und SDK.js. Diese Dateien
sind NICHT im Git und muessen manuell erstellt werden.

  # --- LIVE (piber) ---

  # Backend/.env:
  SHEET_ID=1E1CYezDcScIBvH9ebjN0hOkvttTdA6PFIgYKDMaeE04
  PORT=8080
  COURT_URL=https://scorer-tennis.b-cdn.net/json/24.voll.json
  GOOGLE_APPLICATION_CREDENTIALS=/srv/http/ePiber/piber/Backend/service-account.json

  # Frontend/JS/SDK.js:
  export const BACKEND_WS_URL = "wss://epiber.at/ws";

  # --- PAJ ---

  # Backend/.env:
  SHEET_ID=1auOvEer7i1PW7LO4QX73188Q81Q6QguGyt0zadIIaqo
  PORT=8083
  COURT_URL=https://scorer-tennis.b-cdn.net/json/24.voll.json
  GOOGLE_APPLICATION_CREDENTIALS=/srv/http/ePiber/paj/Backend/service-account.json

  # Frontend/JS/SDK.js:
  export const BACKEND_WS_URL = "ws://epiber.at:8081/ws";

  # --- PK ---

  # Backend/.env:
  SHEET_ID=<PK-Sheet-ID>
  PORT=8084
  COURT_URL=https://scorer-tennis.b-cdn.net/json/24.voll.json
  GOOGLE_APPLICATION_CREDENTIALS=/srv/http/ePiber/pk/Backend/service-account.json

  # Frontend/JS/SDK.js:
  export const BACKEND_WS_URL = "ws://epiber.at:8082/ws";


4.7 Google-Service-Account-Schluessel
--------------------------------------

  Die JSON-Schluesseldatei vom Google Cloud Projekt "e-piber" herunterladen:
    Google Cloud Console → IAM → Service Accounts → Keys → Add Key → JSON

  Die Datei als "service-account.json" in jedes Backend/ legen:
    /srv/http/ePiber/piber/Backend/service-account.json
    /srv/http/ePiber/paj/Backend/service-account.json
    /srv/http/ePiber/pk/Backend/service-account.json

  Besitzer und Rechte der lokalen Backend-Konfiguration setzen:
    chown piber:piber /srv/http/ePiber/piber/Backend/{.env,service-account.json}
    chown paj:paj     /srv/http/ePiber/paj/Backend/{.env,service-account.json}
    chown pk:pk       /srv/http/ePiber/pk/Backend/{.env,service-account.json}
    chmod 600 /srv/http/ePiber/{piber,paj,pk}/Backend/{.env,service-account.json}

  WICHTIG: Der Service Account braucht Bearbeiter-Zugriff auf alle
  3 Google Spreadsheets!


4.8 Caddyfile installieren
---------------------------

  cp /srv/http/ePiber/piber/Project/server-configs/Caddyfile /etc/caddy/Caddyfile
  systemctl enable --now caddy


4.9 Systemd-Services installieren
----------------------------------

  cp /srv/http/ePiber/piber/Project/server-configs/systemd/*.service /etc/systemd/system/
  systemctl daemon-reload
  systemctl enable --now epiber-piber
  systemctl enable --now epiber-paj
  systemctl enable --now epiber-pk


4.10 Firewall oeffnen
---------------------

  Ports 443 (HTTPS), 80 (HTTP Redirect), 8081 und 8082 muessen offen sein.

  # Bei iptables:
  iptables -A INPUT -p tcp --dport 80 -j ACCEPT
  iptables -A INPUT -p tcp --dport 443 -j ACCEPT
  iptables -A INPUT -p tcp --dport 8081 -j ACCEPT
  iptables -A INPUT -p tcp --dport 8082 -j ACCEPT

  # Bei firewalld:
  firewall-cmd --permanent --add-port=80/tcp
  firewall-cmd --permanent --add-port=443/tcp
  firewall-cmd --permanent --add-port=8081/tcp
  firewall-cmd --permanent --add-port=8082/tcp
  firewall-cmd --reload


4.11 DNS
--------

  A-Record: epiber.at → <Server-IP>

  Caddy holt sich automatisch ein Let's Encrypt Zertifikat, sobald der
  A-Record korrekt auf den Server zeigt und Port 80/443 erreichbar ist.
