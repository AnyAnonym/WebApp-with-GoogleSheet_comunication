================================================================================
VERSIONIERUNG.txt — Versionierungs- und Dokumentationsregeln
================================================================================

================================================================================
1. SEMANTIC VERSIONING
================================================================================

Format: MAJOR.MINOR.PATCH

  MAJOR   Inkompatible Aenderungen (DB-Schema, API-Bruch, Architektur-Umbau)
  MINOR   Neue Features, neue Seiten, neue Endpoints
  PATCH   Bugfixes, Refactoring, Performance, Dokumentation, Style

Einzige Quelle der Versionsnummer:
  Backend/package.json  →  Feld "version"

Abrufbar ueber:
  GET /version  →  {"version":"3.0.2"}


================================================================================
2. COMMIT-FORMAT
================================================================================

  <VERSION> <type>(<scope>): <Beschreibung>

  [optionaler Body]

  [optionaler Footer]

Beispiele:
  3.1.0 feat(scoreboard): Live-Score Overlay hinzugefuegt
  3.0.3 fix(matches): Datumsfilter schloss Matches ohne Datum nicht aus
  4.0.0 breaking(database): Matches1 Spalten umbenannt


================================================================================
3. COMMIT TYPES
================================================================================

  Type       | Versions-Effekt | Beschreibung
  -----------|-----------------|--------------------------------------------
  feat       | MINOR           | Neues Feature oder Funktionalitaet
  fix        | PATCH           | Bugfix
  docs       | PATCH           | Dokumentation
  style      | PATCH           | Code-Formatierung (kein Logik-Aenderung)
  refactor   | PATCH           | Umbau ohne neue Features oder Fixes
  perf       | PATCH           | Performance-Verbesserung
  test       | PATCH           | Tests hinzufuegen oder anpassen
  breaking   | MAJOR           | Inkompatible Aenderung


================================================================================
4. COMMIT SCOPES
================================================================================

  Scope       | Bereich
  ------------|-----------------------------------------------
  matches     | Match-Management (Matches1, matches, preMatches)
  scoreboard  | Scoreboard und Live-Scores
  navigator   | Navigator und Monitor-Steuerung
  entryList   | Eintragungslisten
  ranking     | Ranglisten-Funktionalitaet
  roundRobin  | Gruppenspiel-Ansicht
  bracket     | Turnierraster / KO-Baum
  bewerbe     | Bewerbe-Verwaltung
  players     | Spieler-Verwaltung
  backend     | Backend-Module (server, poller, provider, store)
  ui          | Frontend / UI allgemein
  config      | Konfiguration (.env, SDK.js, Caddy, systemd)
  database    | Spreadsheet-Schema / Tabellenstruktur
  infra       | Server-Infrastruktur
  docs        | Dokumentation


================================================================================
5. DOKUMENTATIONSREGELN — WAS WIRD DOKUMENTIERT
================================================================================

Bei jeder neuen Version wird geprueft, welche Dokumentationsdateien
aktualisiert werden muessen. Die Documentation stellt immer den
AKTUELLEN STAND dar — kein historisches Anhaeufeln.

  Aenderungstyp                  | Zu aktualisierende Datei(en)
  -------------------------------|------------------------------------------
  Server/Infrastruktur geaendert | server-configs/CHANGELOG.txt
                                 | server-configs/SERVER-SETUP.txt (bei Bedarf)
                                 | server-configs/Caddyfile (bei Bedarf)
                                 | server-configs/systemd/*.service (bei Bedarf)
  Software geaendert             | software/CHANGELOG.txt
  Datenbank-Schema geaendert     | software/DATENBANK.txt
  Endpoint hinzugefuegt/geaendert| software/ENDPOINTS.txt
  HTML-Seite geaendert           | software/seiten/<seite>.txt
  Architektur geaendert          | software/ARCHITEKTUR.txt
  Deployment-Ablauf geaendert    | Project/DEPLOYMENT.txt
  Neue Seite erstellt            | software/seiten/<neue-seite>.txt
                                 | software/SOFTWARE-DOKU.txt (Seitenliste)
                                 | LLM-KONTEXT.md (Seitentabelle)

Versionsnummer aktualisieren:
  Backend/package.json  →  "version" Feld aendern
  (Frontend holt die Version automatisch per fetch("/version"))


================================================================================
6. CHANGELOG-FORMAT
================================================================================

Beide Changelog-Dateien verwenden dasselbe Format:

  [<VERSION>] - <DATUM>

    Added
    - Neue Funktionen oder Dateien

    Changed
    - Aenderungen an bestehender Funktionalitaet

    Fixed
    - Behobene Fehler

    Removed
    - Entfernte Funktionen oder Dateien

Leere Kategorien werden weggelassen.
Eintraege sind kurz und praegnant (1 Zeile pro Aenderung).

Dateien:
  server-configs/CHANGELOG.txt  →  Nur Server-/Infrastruktur-Aenderungen
  software/CHANGELOG.txt        →  Nur Software-Aenderungen (Features, Fixes, UI)


================================================================================
7. WORKFLOW BEI NEUER VERSION
================================================================================

Schritt 1: Code aendern und testen

Schritt 2: Versionsnummer in Backend/package.json erhoehen
           (MAJOR/MINOR/PATCH gemaess Regeln in Abschnitt 1)

Schritt 3: Commit erstellen
           Format: <VERSION> <type>(<scope>): <Beschreibung>

Schritt 4: Dokumentation aktualisieren (siehe Abschnitt 5)
           - Betroffene Doku-Dateien pruefen und anpassen
           - CHANGELOG-Eintrag(e) ergaenzen

Schritt 5: Deployment (siehe Project/DEPLOYMENT.txt)
           - git push
           - Server: git pull + ggf. npm install + ggf. systemctl restart

Hinweis: Bei LLM-gestuetzter Protokollierung wird dieser Workflow
         als Aufforderung gestellt ("Version X.Y.Z protokollieren").
         Das LLM fuehrt dann Schritte 3-4 durch.


================================================================================
8. ARCHIVIERTE DATEIEN
================================================================================

Die folgenden Dateien werden NICHT mehr aktualisiert:

  Project/PROTOKOLL.txt     →  Ersetzt durch software/CHANGELOG.txt
                                und server-configs/CHANGELOG.txt
  Project/DB.txt            →  Ersetzt durch software/DATENBANK.txt
  Project/Seiten.txt        →  Ersetzt durch software/seiten/*.txt
  Project/copilot-instructions.md  →  Ersetzt durch diese Datei
