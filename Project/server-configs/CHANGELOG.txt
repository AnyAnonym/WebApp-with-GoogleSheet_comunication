================================================================================
CHANGELOG — Server-Infrastruktur
================================================================================
Stand: v3.0.2

Dieses Changelog dokumentiert ausschliesslich server- und infrastrukturbezogene
Aenderungen (Caddy, systemd, Firewall, DNS, Konfigurationsdateien, Deployment).

Software-Aenderungen (Frontend, Backend, Features) werden in PROTOKOLL.txt
dokumentiert.

Format: Added / Changed / Fixed / Removed (Semantic Versioning)


================================================================================
[3.0.2] - 2026-07-22
================================================================================

  Added
  - Google Service Account Keys erstellt und auf allen 3 Systemen eingerichtet

  Changed
  - Backend/.env und Frontend/JS/SDK.js pro System konfiguriert (Live / PAJ / PK)


================================================================================
[3.0.1] - 2026-07-22
================================================================================

  Fixed
  - PAJ/PK WebSocket-URLs in SERVER-SETUP.txt auf ws:// korrigiert (HTTP, nicht HTTPS)
  - /version Endpoint in Status-Pruefung dokumentiert


================================================================================
[3.0.0] - 2026-07-21
================================================================================

  Added
  - Caddy Webserver als Reverse Proxy mit automatischem Let's Encrypt TLS (Live)
  - 3 systemd-Services: epiber-piber.service, epiber-paj.service, epiber-pk.service
  - Firewall-Regeln fuer Ports 80, 443, 8081, 8082
  - DNS A-Record fuer epiber.at
  - Backend config.js liest SHEET_ID, PORT, COURT_URL aus Umgebungsvariablen
  - .env und .env.example fuer Backend-Konfiguration pro System
  - SDK.js.example fuer Frontend WebSocket-URL pro System
  - HTTP-Endpoints: /health, /version, /status, /set-active
  - Zentrale Versionierung: Backend/package.json als einzige Quelle, GET /version
  - Project/server-configs/ Verzeichnis mit Caddyfile und systemd-Vorlagen
  - Project/DEPLOYMENT.txt fuer Deployment-Workflow

  Changed
  - Migration von Google Cloud (Firebase Hosting + Cloud Run) auf eigenen Arch Linux Server
  - 3 Systeme auf einem Server: piber (HTTPS:443/8080), paj (HTTP:8081/8083), pk (HTTP:8082/8084)
  - Server-Verzeichnisse: /srv/http/ePiber/{piber,paj,pk}/
  - Konfigurationsdateien pro System manuell erstellt (nicht im Git)

  Removed
  - Firebase Hosting
  - Google Cloud Run
  - Dockerfile
  - firebase.json, firestore.rules, firestore.indexes.json
  - Root package.json und package-lock.json (waren nur fuer Firebase)
